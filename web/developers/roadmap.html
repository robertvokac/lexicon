Roadmap & TODO

Lexicon now does what it set out to do. New features wait while it is used day to day; what comes next is what that use shows is missing.

Recently shipped

  • LexiconServer with a versioned REST API, and two clients for it: the web client and the Android app.
  • Search that ignores case and diacritics and ranks exact titles first.
  • Conflicts: a save based on an item another client changed meanwhile is refused with a choice to overwrite or reload.
  • Export and import of the whole dictionary in documented JSON format version 2, including cards and their attempt counts.
  • Review with spaced repetition, [[wiki links]] between items, and a relationship graph.
  • An Inbox for quick ideas, marked with an Inbox item type and available offline on Android.
  • Alarms that ring in every client, Image values, and automatic server backups.
  • Cards on items, with a Yes/No quiz over one item or its relationship neighbourhood, kept apart from Review.

Ideas for later

Not promises — candidates, once day-to-day use asks for them.

🌐 Export to static HTML

Publish a whole lexicon as a browsable static website — sharing your knowledge base without sharing the app.

📊 Export to CSV

Items and their values as a table, for spreadsheets and scripts.

🗑️ Trash and item history

Undo a deletion or go back to an earlier version of an item.

⏰ Recurring alarms

Alarms that repeat, and alarms that belong to an item.

💾 Desktop backups

The server's automatic backups for people who use only the desktop client.

🧱 More unique indexes

Additional database constraints to guarantee consistency as the schema grows.

Working TODO list

TODO.md in the repository holds the smaller polish items:

  • Improve table column density and wrapping for long Tags, Aliases, and Flags.
  • Review resizing between the item table, content preview, and links area.
  • Add keyboard shortcuts for common item actions.
  • Add undo/redo for edits spanning multiple item fields or links.
💡

Want one of these? Open an issue to discuss it first, and see Contributing for the workflow. Small, focused pull requests are the easiest to review and merge.
