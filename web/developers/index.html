Developer Docs

Everything you need to build, understand, and extend Lexicon. The codebase is small, focused, and easy to get into — a classic Qt Widgets desktop application with a clean data layer.

Technology stack

LayerTechnologyNotes
LanguageC++23CMAKE_CXX_STANDARD 23, extensions off
GUIQt 6 WidgetsClassic desktop widgets, no QML
PersistenceSQLite via Qt SQLSingle-file database with versioned migrations
Markdownmd4qtVendored in 3rdparty/, compiled into the binary
Build systemCMake ≥ 3.21Single Lexicon executable target
LicenseMITFree for any use

Repository layout

lexicon/
├── CMakeLists.txt        # single-target CMake build
├── src/
│   ├── main.cpp              # entry point: DB init + MainWindow
│   ├── MainWindow.{h,cpp}    # main window: filters, table, pagination, preview
│   ├── ItemEditDialog.{h,cpp}# 5-tab item editor
│   ├── GroupManagerDialog.{h,cpp}  # group CRUD dialog
│   ├── ValueListDialog.{h,cpp}   # read-only tag/flag/alias overviews
│   ├── DatabaseManager.{h,cpp}   # all SQL: schema, migrations, queries
│   └── MarkdownConverter.{h,cpp} # Markdown → HTML via md4qt
├── 3rdparty/md4qt/       # vendored Markdown parser
├── resources/            # application icon
├── images/               # screenshots used by README and this site
├── lexicon.desktop       # Linux desktop entry
└── LICENSE               # MIT

How it fits together

  1. main.cpp initializes the database (creating lexicon.db next to the executable and applying migrations), then shows the MainWindow.
  2. MainWindow drives the whole browsing experience — filters, search, the paginated item table, and the rendered preview pane.
  3. Dialogs (ItemEditDialog, GroupManagerDialog, ValueListDialog) handle editing and overviews.
  4. DatabaseManager is the single gateway to SQLite — a static API used by all UI classes. No SQL lives outside it.
  5. MarkdownConverter turns item content into HTML for the preview panes using md4qt.
