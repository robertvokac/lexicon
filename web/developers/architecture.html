Architecture

Qt Widgets is one frontend for a framework-independent Lexicon backend.

Layers and dependencies

TargetResponsibility and dependencies
lexicon-coreRecords, validation, and comparison policy. Standard C++ only.
lexicon-applicationServices and the Repository interface. Depends on core only.
lexicon-storage-sqliteNative SQLite implementation of Repository. Depends on application, SQLite C API, and OpenSSL Crypto. No Qt.
lexicon-qt-bridgeQt and UTF-8 standard C++ value conversions. Depends on core and QtCore.
Lexicon (lexicon-qt/)Qt Widgets frontend and desktop composition root. Injects the SQLite repository into application services. Contains no SQL.
lexicon-core
      ↑
lexicon-application ← lexicon-storage-sqlite
      ↑                         ↑
lexicon-qt-bridge          SQLite C API
      ↑
lexicon-qt (Qt Widgets; composition root)

Core, application, and SQLite storage can be configured, built, and tested without Qt. CMake rejects Qt links in these targets.

Repository and transaction ownership

Application services use the Repository interface and return std::expected<T, Error>. Only the storage implementation owns sqlite3 connections and prepared statements. RAII finalizes statements and rolls back unfinished savepoints. The application defines the item and links unit of work in ItemService::saveItemWithLinks; repository writes use nested savepoints.

Migrations.cpp retains the existing schema and migration versions. Databases created by the former QtSql implementation remain compatible, including enum options stored as compact JSON arrays. Blob bytes live beside the database under blobs/ and use SHA-256 identifiers.

UTF-8 and comparison

Core, application, and storage use UTF-8 std::string. Qt conversions occur at the desktop boundary. Case-insensitive matching folds ASCII letters only; non-ASCII UTF-8 bytes compare exactly. This matches SQLite NOCASE, LOWER, and default LIKE. Exact lookups and constraints without NOCASE remain byte-exact. The backend does not implement Unicode case folding.

Future client

A future lexicon-http executable can compose lexicon-application with lexicon-storage-sqlite without linking Qt. No server is part of the current application.
